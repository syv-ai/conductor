    Conductor 2.0

    Conductor is a Python library that runs graphs of typed nodes. You write Python functions. Someone else wires them together in an editor, and the graph reaches you as JSON. Conductor checks that graph, tells you what's wrong with it, and runs it.

    It needs only pydantic, polars and typing-extensions. It has no web framework, database or login, and it uses none of a host's words. Those belong to the application that uses it, which conductor calls the host.

    A node is a typed function.

    Its parameters are its inputs and its return type is its outputs. Nothing is declared twice.

    @node("shout", title="Shout", description="…")
def shout(line: str) -> str:
    return line.upper()

    A graph is a JSON record.

    An editor saves it, and code writes the same record with make_graph. You compile it against a registry.

    {
  "nodes": {
    "shout": {
      "node": "shout",
      "inputs": {
        "line": {
          "graph_input": "line"
        }
      }
    }
  },
  "outputs": {
    "result": {
      "node": "shout",
      "output": "result"
    }
  }
}

    A run is JSON you save and resume.

    It can wait days for a person, then go on in another process. A call that's finished in the saved run isn't made again.

    saved = run.to_json()
# days later, anywhere
run = Run.from_json(saved, graph)
run.answer(run.waiting[0], True).resume()

    Publicwhat you import, write or read back

    Internalhow conductor does it inside; you never import it, and it can change in any release

    The map

    Five public modules in front of eleven internal layers

    A host imports only the five public modules on top. The engine behind them is the packages under conductor._internal, in layers that an import-linter contract in pyproject.toml declares. A package imports only from the layers below it. The one exception is graph/type.py, which imports run. Packages on one line import none of each other.     Against main

    Runs are much faster, and compiling is slower

    Three workloads were timed on 1.12.2 and on 2.0. Each row is drawn to its own scale, set by its slower bar, so the lengths in a row compare directly.

    1.12.2 (main)2.0, faster2.0, slower

    What compiling does now. 2.0 checks that the types at the two ends of each edge fit when it compiles. Nobody has profiled which part of compiling makes it slower than 1.12.2.

    A host that keeps the Graph pays this once. conductor-providers compiles again each time it loads a run, so a served run pays it on every answer and resume.

    Why it's built this way

    Twelve design choices and the reason for each

    The full case, with what each choice costs, is in docs/design.md.

    A node is a typed function, and its signature is its interface.Public

    The engine, the checks and the editor all read the one signature, so nothing is declared twice. A node is still callable like its function, which makes calling it its unit test.

    More

    @node registers nothing. It returns a frozen definition that can go into any registry, so what a host offers is written in one place. See A node and its types.

    Cost: nobody can find a node until it's added to a registry.

    A graph is data, and there's no @graph.Public

    Most graphs are drawn in an editor, and a graph built in code is the same record the editor saves. Two ways to define a graph would mean two sets of rules.

    More

    Each input gets exactly one thing: a constant, a graph_input, or the sources of its edges. No rule has to say which one wins. See The graph record and compiling.

    Compiling reports problems instead of raising.Public

    Each fault is a Problem with a stable type, tied to a place in the graph, so an editor can mark it where it is. A half-finished graph still compiles. Compiling raises only when it isn't given a graph record at all (invalid_record). Running a graph that isn't runnable raises.

    More

    The same Problem record is in graph.problems, on a node_failed event, in a run's cause and on every error conductor raises (InvalidCallError, NodeDeclarationError). A host translates it by type. See Problems.

    The types decide one or many.Public

    A Series[T] output wired to an input of one T runs that node once per item. A Series input collects them again. A "loop over this" flag would say what the types already say.

    More

    A caller's list never starts a loop, so an editor can show in advance how often a node runs. See Series and tables.

    Cost: a list sent to a str input is refused where it could have looped, and a table needs a Split node before anything runs per record.

    Behaviour is a value, not a flag.Public

    A branch not chosen returns SKIPPED. A node that needs a person raises Ask, and its @node says asks=True.

    More

    The return type says what the answer is, and the answer becomes the node's outputs, as if it had returned them. See Asking a person.

    Cost: the signature alone doesn't say a node may ask. asks=True does, and registry.describe() shows it on each node.

    A value from outside is checked once, where it comes in.

    Each place a value comes in has its own check: a graph record, a caller's inputs, an answer, what a node returns. Past those places the engine trusts what it has. The one check inside is an edge whose input demands more than its source declares.

    You see a bad value refused at the place it comes in.

    Cost: an edge whose input demands more than its source declares has each value it carries checked as the run goes.

    More

    Internal Each check is a Validator in its package's validator.py. A saved run is read by its codec in run/json/.

    One scheduler runs a run, with or without a listener.

    run.resume() and run.stream() call the nodes the same way. Streaming only adds the events. So what a test sees with resume() is what a served run does.

    You see resume(), stream() and a node's Policy.

    More

    Nodes run on the scheduler's own thread by default. A node asks for threads by setting concurrency above 1 or an attempt_timeout, since threads by default would surprise code that isn't thread-safe. See Running and streaming.

    Cost: a host whose slow nodes forget concurrency runs them one at a time within a run.

    Retries belong to the node's Policy.Public

    Only an ExternalError, or a class the node's retry_on names, is retried. A NodeError other than ExternalError, and a refused output, never are, since calling again would give the same result.

    More

    Retry n waits retry_delay * 2 ** (n - 1). See Running and streaming.

    A run is one JSON text.Public

    run.to_json() writes it and Run.from_json(saved, graph) reads it back, refusing a run of another graph by its fingerprint. So a run can wait for days and pick up again in another process.

    More

    With stream(checkpoint_every=), a process that dies repeats the calls in flight and those recorded since the last checkpoint. See Saved runs and reuse.

    Running again reuses by content.Public

    A call that gets exactly the arguments a call of the same node got before, under the same version and code, reuses that outcome. Add one line to a CSV of 5,000, and a node that runs per line is called for the new one only.

    More

    It works across an edit of the graph too, with with_inputs(previous=old_run). See Saved runs and reuse.

    Cost: the code in the key is the node function's own, so a change to a helper it calls isn't noticed. A node that depends on more than its inputs sets Policy(reuse_when_inputs_match=False).

    The core stands alone.

    Fitting it to one platform would make it narrower and the code no better.

    You bring your own storage and login.

    More

    With conductor-providers, RunStore is six async methods the host writes. See Serving runs.

    Cost: shipping no store means every host writes one, on storage it already has.

    A rule is written once in the reference.Public

    llms.txt, printed by python -m conductor.about, is the one complete reference. The other pages teach by example and point there, so each rule has one place to change.

    More

    Internal The reference keeps no hand-written copy of what the code declares. Its list of public names is written in from each module's __all__ and docstrings, and the problems page is written from the function that declares each kind of problem.
