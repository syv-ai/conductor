    Save a run and run it again

    A run is one JSON text. You can store it, load it in another process and go on. When you run a graph again with one thing changed, a call whose arguments conductor has seen before, under the same code, takes its earlier outcome instead of running.

    Saving is run.to_json() and Run.from_json(saved, graph). Running again is run.again(...) and graph.with_inputs(previous=run).

    The examples use one small graph. lines splits a text into lines, shout runs once per line, and join gets all of shout's results back as one list.

    Where a sample prints the calls made, it ran a copy of these nodes that also records each call. The hashes on this page come from the nodes exactly as shown.

    @registry.node("lines", title="Lines", description="The lines of a text.")
def lines(text: str) -> Series[str]:
    return text.splitlines()

@registry.node("shout", title="Shout", description="Shouts a line.")
def shout(line: str, mark: str = "!") -> str:
    return line.upper() + mark

@registry.node("join", title="Join", description="Joins every text it is given.")
def join(texts: Series[str], sep: str = "+") -> str:
    return sep.join(texts)

record = make_graph(lines, shout, join)
graph = Graph.compile(record, registry)

    A run as JSON

    A saved run keeps one list per output, with one entry per call

    InternalIn memory, a run keeps one outcome per call, keyed by the call's item indexes. shout has three calls, at (0,), (1,) and (2,).

    PublicThe saved JSON has a list of states for each node, a list for each of its outputs, and a list of call fingerprints. A call's place in the lists is its call number.

    The finished run as saved

    This run was made on "a\nb\nc" and then saved. to_json() writes it on one line, 547 characters. The sample prints it with dumps, a small helper that indents by 2 and keeps a list that fits on one line on one line. Each entry under fingerprints is a call's fingerprint, taken when the call was made: a hash of the node's code fingerprint and the call's arguments. The code fingerprint hashes the node's id, version, fields, loops and whether it asks, with the function's parsed source, so it is the same on any Python version. So is the graph fingerprint, which holds no code.

    A call that isn't done

    A call with no outputs has null in every list. Only a done or a waiting call can have a fingerprint. A waiting call says why under questions, which holds what its Ask said. The page on asking a person shows one. A call not made because an input got None says why under none_inputs. A skipped call has the state "skipped". A failed call has only the nulls, and ended_early holds the problem. Here strip returned None for the blank second part of "a, ,c", and up(line: str) doesn't take None, so it wasn't called for it. Below is the value of outcomes.up.

    Every key of a saved run

    A key that isn't declared is refused, not dropped. A key that has a default (questions, none_inputs, skipped, skipped_items, and in a reusable entry item_indexes) is left out when it is empty. The top-level keys are always written.

    graph

    It is the graph's fingerprint, graph.fingerprint. It hashes the graph record without each node's display, and each subgraph's fingerprint. A saved run of another graph is refused by it.

    ended_early

    It says how the last resume() ended the run early. It holds the status and the problem. It is null when it didn't. A copy made while a resume is still going is saved with null here.

    max_items

    The run's item limit.

    inputs

    The graph inputs the caller gave, by name.

    outcomes

    It holds the lists above for each function node that has an outcome: states, outputs and fingerprints, then the keys that say why a call isn't done. A node inside a subgraph is named by its path, loud/shout. A subgraph node is never called, so it has no key.

    reusable

    It holds the previous run's outcomes this run may still reuse, by node. Each outcome is written once, in the same lists as under outcomes, with the fingerprint its call was made with, and the item indexes the call had beside it. It has entries in a run made from a previous run, for the nodes that aren't complete yet.

    complete

    The nodes that were complete when the run last stopped, so going on doesn't report them complete again.

    Reading it back

    A saved run is checked against its graph when it is read

    A saved run comes from a store, so Run.from_json checks it where it comes in. Any fault in it is one saved_run_unreadable: ctx.where names its place, ctx.reason says why, and ctx.errors holds the one error, with no value in it. A saved run of another graph is saved_run_of_another_graph instead. A graph with problems raises those before anything is read.

    A value of the wrong type

    Put 7 where shout's second result was. shout's result is declared a str.

    data["outcomes"]["shout"]["outputs"]["result"][1] = 7
try:

except InvalidCallError as e:

    A value is saved by its output's type

    Each value is written by its output's type. A call with no outputs has null in every list. run.outputs_to_json() writes a complete run's graph outputs by the same types. The page on Series and tables has how a run stores a Series.

    Each value reads back by its declared type, so a date comes back from its text. JSON has no number for inf or nan, so they are written as the texts "Infinity", "-Infinity" and "NaN". A float reads the float back. Under Any, the text stays text. bytes are written as base64 text, as in all JSON conductor writes (conductor.JSON_CONFIG).

    What a call is matched by
    
      
      
        
    • A dict a database hands back with its keys in another order still matches.
      • 
        
    • The fingerprint is taken once, when the call is made, and kept on its outcome, a saved run's too. So an outcome made before the node's code changed keeps the old code in its fingerprint, and no call of the new code matches it.
      • 
        
    • An argument with no JSON form gets no fingerprint. That call is made again, and the run doesn't fail.
      • 
        
    • Input types are part of the code fingerprint, limits and choices too. So a node whose input's limit changed is called again, since its input may refuse the same value.
      • 
      
    
      
    
    
  
    

    


    



    
  
    
    
    A node that may ask
    
    
    Answers are reused once each and in item order Public
    
    
    Two calls with the same arguments may have been answered differently. So a node with asks=True doesn't share one outcome between them. Each earlier outcome is reused once, by the calls with those arguments, in item order, and then taken out. A question still waiting goes on waiting at its item's new place. A call beyond the outcomes there were is made again.
    
  
    
  
    
    
    
      
    r = NodeRegistry()

@r.node("names", title="Names", description="Names.")
def names(text: str) -> Series[str]:
    return text.split(",")

@r.node("approve", title="Approve", description="Asks.", asks=True)
def approve(name: str) -> bool:
    raise Ask(f"Approve {name}?")

g = Graph.compile(make_graph(names, approve), r)
run = g.run({"text": "bo,bo"})
run = run.with_answers({w.id: v for w, v in zip(run.waiting, (True, False))}).resume()
print(run.results["approve"]["result"])
again = run.again({"text": "eva,bo,bo"})
print(again.results["approve"]["result"], [w.id for w in again.waiting])

    Eva is new, so she is asked. The first bo keeps the first answer and the second keeps the second, even though both moved down one place.
    
      
    The same holds for what such a node returned without asking. Whether a node asks is part of its code fingerprint, so the two kinds of outcome never mix.
    
      
    An answer is also tied to its outer items. When a node is inside two loops, say lines inside documents, two documents' identical lines keep their own answers when the documents swap. An answer is tied to the whole document it was given in, so a change anywhere in a document asks again about every line of it.

    What is kept of a previous run
    
    
    A run made from a previous one keeps a function node's previous outcomes under reusable. It keeps them only when the new graph has a node at the same path, with the same code fingerprint, and a Policy that allows reuse.
    
    
      
      
    • It keeps the calls that were made: their results, and a question still waiting. A skipped call, or one not made because an input got None, has nothing to reuse.
      • 
      
    • It also carries on what the previous run could have reused and didn't, for each node that isn't complete. When a node is complete, its unused reusable outcomes are dropped.
      • 
      
    • run.with_forgotten("node") is a run of the same inputs without that node's reusable outcomes, so that node is called again. A node downstream that then gets the same arguments is reused.
      • 
    
    
  
    

    


    



    
  
    
    
    What a node says about itself
    
    
    Two settings on Policy Public
    
    
    reuse_when_inputs_match=False is for a node that reads the outside world, not only its inputs, like a file read by its path or today's exchange rate. A run made from a previous one calls it for every item, once the policy is in the graph the new run is made from. Run.from_json checks the policy too. It drops what a saved run could still reuse for a node whose policy says False now.
    
    
    costs_nothing=True is for a cheap node that touches nothing outside the run. run.resume(only_costs_nothing=True) calls only such nodes, so a host can see how many calls the costly nodes will make before any of them runs.
    
  
    
  
    
    
    
      
    calls = []
registry = NodeRegistry()

@registry.node("files", title="Files", description="The names of the files.",
               policy=Policy(costs_nothing=True))
def files(names: str) -> Series[str]:
    calls.append("files")
    return names.split(",")

@registry.node("rate", title="Rate", description="Today's rate for a file.",
               policy=Policy(reuse_when_inputs_match=False))
def rate(name: str) -> str:
    calls.append(f"rate {name}")
    return name + " rated"

graph = Graph.compile(make_graph(files, rate), registry)
first = graph.with_inputs({"names": "a.pdf,b.pdf"}).resume(only_costs_nothing=True)
print(calls, first.status, first.progress.nodes["rate"].total)
calls.clear()
done = first.resume()
print(calls, done.status)
calls.clear()
again = done.again()
print(calls)

    Why it's built this way
    
    
    The design choices of this part
    
  
    
  
    
    
    
      
    A saved run has a list per output, not a record per call.Public
    
      
    Pydantic checks a whole list in one go, where a record per call would cost a check each. Each output's name is written once. And a call too many or too few makes a list of the wrong length, which reading refuses.
    
      
    Cost: one call's outcome is spread across several lists (its states, outputs and fingerprints), and the extra keys (questions, none_inputs, skipped, skipped_items) point back into them by call number.
    
    
    
    
    
      
    Item indexes aren't saved.Public
    
      
    Reading works them out from the lengths of the series upstream, so a saved run can't name a call the graph wouldn't make.
    
      
    Cost: reading goes node by node, in the order a run tries them, since each node's calls depend on the nodes before it.
    
    
    
    
    
      
    Each graph gets its own codec.Internal
    
      
    The node names, output names and value types are fields of one pydantic model, so a single pass checks every key and value, and an error comes with the place it is in. What you see of it is the place a saved_run_unreadable names.
    
      
    Cost: the codec is built the first time a run of the graph is saved or loaded. Nodes whose outputs have the same names and types share one class, which keeps a large graph's codec small.
    
    
    
    
    
      
    Loading checks the graph and reuse checks the node.Public
    
      
    A saved run only makes sense against the graph it ran on, so the graph fingerprint gates from_json. Work is worth keeping across an edit, so reuse is decided per node by its code fingerprint, through previous=.
    
      
    Cost: any edit to the record other than display means a new run. The saved run of the old graph can't be loaded into it.
    
    
    
    
    
      
    Reuse goes by content, not by place.Public
    
      
    Insert a line, reorder the lines, or repeat one, and the calls that see a value they saw before take its outcome.
    
      
    Cost: every call's arguments are written as JSON and hashed when the call is made, since its outcome keeps the fingerprint. A call with an argument that has no JSON form isn't reused.
    
    
    
    
    
      
    The code in the key is the function's own.Public
    
      
    The code fingerprint takes the function's source as Python parses it, without its name, decorators, comments and docstrings. So a docstring edit keeps the outcomes, and so does a new Python version. Hashing all the code a node can reach would be slow, and would still miss the outside world.
    
      
    Cost: a change to anything the function reads from outside its own source isn't noticed: a module constant such as a prompt template, a helper it calls, a method of a type it uses, a data file it opens. To call the node again, make the run with run.with_forgotten("node"), or declare a new version of the node and move the graph to it with registry.upgrade. A node whose result depends on more than its inputs on every call sets reuse_when_inputs_match=False. A function whose source conductor can't read is hashed by its bytecode: a lambda, a function made by exec, or one defined where Python keeps no source. A def's bytecode includes its docstring. Bytecode changes with the Python version, so after a new one nothing of such a node is reused, answers included, and its waiting calls' ids change.
    
    
    
    
    
      
    The context is not in the key.Public
    
      
    The context is the host's objects for one run. It is never saved, so it can't be compared with the previous run's.
    
      
    Cost: a node whose result depends on the context still has its outcome reused when its arguments match, unless its policy says no.
    
    
    
    
    
      
    Unused outcomes are dropped once a node is complete.Public
    
      
    Without the drop, a saved run would grow with every edit. A test edits one row of a 10,000-row input five times, and the saved run's size varies by less than 100 characters. A node that isn't complete keeps them, such as one with a question still waiting, so an answer survives an edit and its revert.
    
      
    Cost: undoing an edit in the next run calls the node again for the items the edit took out. Going from a,b,c to a,b,d and back to a,b,c calls shout("c") again.
