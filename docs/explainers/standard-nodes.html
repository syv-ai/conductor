    The standard nodes

    syv-conductor-nodes is a separate package of 36 ready-made nodes. They work on text, numbers, yes or no, JSON, regular expressions, lists and tables, and three of them choose where a value goes. They work only on the values they're given.

    A host adds the ones it wants to its own registry, next to the nodes it writes itself. You import it as conductor_nodes. Every output on this page was printed by the code it shows.

    Back to the overview

    A registry per module

    Each of the eight modules is one category, with a registry of its own. conductor_nodes.registry has all 36 nodes.

    Nodes written like a host's

    The package imports eight names, from conductor and conductor.widgets, and nothing from conductor._internal.

    Types that follow the edge

    A node that passes a value on is generic in T. Its outputs take the type of what is wired into it.

    Publicwhat you import, write or read back

    Internalhow conductor does it inside; you never import it, and it can change in any release

    How it's grouped

    Every module is one category

    Each module starts with registry = NodeRegistry(category="math"), or its own category, and declares its nodes on it with @registry.node. A node takes the category of the registry it's declared on, so every node in conductor_nodes.math is in math. conductor_nodes.registry then adds the eight registries into one.

    What it's built on
    
    
    The package imports eight public names Public
    
    
    Conductor's rules say the companion packages import only its five public modules. conductor_nodes imports these eight names from two of them.
    
  
    
  
    
    
    
      
    from conductor import NodeError, NodeRegistry, Param, Policy, SKIPPED, Series, Table
from conductor.widgets import Textarea
    
      
    Besides those, the package uses pydantic (for JsonValue), polars, the regex package and typing-extensions, which its pyproject.toml lists with syv-conductor==2.0.0.
    
    
    
    
    Each node is a typed function under @registry.node, with Param where a field needs more than its type. The two pages on a node and its types and on Series and tables explain these names.
    
  
    
  
    
    
    NodeRegistryone per module
    A host makes one and adds the package's nodes to it with add_subregistry. Each node keeps the category of the module it comes from.
    
    
    Serieswhere a loop starts and ends
    A node that returns one starts a loop: text-split, text-list, regex-extract, series-split, and series-collect, whose list can start a new loop. A node that takes one is called once with every item: text-join, math-min, math-max, series-collect, series-stack.
    
    
    Tablea whole table as one value
    series-split takes Table[T] | list[T] and gives its rows or items. series-stack returns Table[R]. table-collect takes a Table and returns one with new columns.
    
    
    Paramtitles, limits, widgets
    It gives output titles such as Sum and Parts. It sets limits that are checked before the node runs, such as ge=0, le=8 on json-stringify.indent, ge=0, le=10 on math-round.decimals, and min_length=1 on text-split.separator and on the needle of text-replace and text-contains.
    
    
    Policycalls that cost nothing
    Every node in the package is declared with policy=Policy(costs_nothing=True), since none touches anything outside the run. So run.resume(only_costs_nothing=True) calls all of them, and the totals after text-split, text-list, regex-extract and series-split are known before any node that costs something is called. A node's own error, such as invalid_pattern, can then fail that call.
    
    
    SKIPPEDa branch not chosen
    A branch is an output whose default is SKIPPED. control-decide gives SKIPPED on the branch not chosen. control-switch returns SKIPPED for every branch but the chosen one.
    
    
    NodeErrora failure with a code
    The package raises it with eleven codes, such as division_by_zero, not_json, invalid_pattern and columns_not_aligned. Raised inside a hook, it becomes a compute_hook_failed problem when the graph is compiled.
    
    
    Textareathe one widget
    It's on the long text inputs only. See below.
    
    
    Hookskeywords of @node
    control-switch has compute_outputs. table-collect has compute_added_inputs and compute_outputs. These are the only two nodes with hooks, and the only two that are set by a constant: cases, columns and constant_columns.
    
  
    

    


    



    
  
    
    
    Choosing a way
    
    
    Decide, switch and default
    
    
    A branch is an output. The chosen branch gets the value, and the others get SKIPPED, so the nodes after them are skipped for that call. Several branches can be wired into one input. That node takes the value of whichever branch was chosen, so there is no node to join the branches again. All three pass value on unchanged.
    
  
    

  
    
    
    
    
      
    
        
    control-decide sends a value one way or the other
    
        
    It sends value to if_true when when is true, and to if_false when it's false. Another node works out the yes or no, and you wire it into when. when has no default, so a graph that neither wires it nor gives it a value is input_has_no_value when it is compiled. Here logic-equals asks whether a text is 2 characters long.
    
        
    The source in control.py Internal
    
        
    @dataclass(frozen=True)
class Decided[T]:
    if_true: Annotated[T, Param(title="If true")] = SKIPPED
    if_false: Annotated[T, Param(title="If false")] = SKIPPED

@registry.node("control-decide", title="Decision", description="...")
def decision[T](value: T, when: bool) -> Decided[T]:
    return Decided(if_true=value) if when else Decided(if_false=value)
    
      
    
      
    
        
    
          
        
    
        
    
          Run it with

    control-switch has a branch per case and one called other
    
        
    Its outputs are named by cases, a constant written in the graph. Its compute_outputs hook reads it when the graph is compiled. With ["invoice", "receipt"] the outputs are invoice, receipt and other. A value whose case is none of them goes down other, so it isn't lost. The hook gets value: type, the type wired into value, and gives each name (value, SKIPPED), so every branch has that type and the default SKIPPED. The match is exact. To ignore upper and lower case, put text-lowercase in front.
    
        
    The source in control.py Internal
    
        
    def _branches(cases: list[str], value: type) -> dict[str, Any]:
    ...  # refuses a case named "other", and a case given twice
    return {name: (value, SKIPPED) for name in [*cases, "other"]}

@registry.node("control-switch", ..., compute_outputs=_branches)
def switch[T](value: T, case: str, cases: list[str]) -> dict[str, Any]:
    taken = case if case in cases else "other"
    return {name: value if name == taken else SKIPPED
            for name in [*cases, "other"]}
    
        
    ['invoice', 'other']  [('compute_hook_failed', 'case_named_other')]
['a', 'b', 'a']       [('compute_hook_failed', 'case_given_twice')]
    
        
    The two refusals are graph.problems of a graph compiled with those cases. Since the hook reads cases, the input takes only a constant, and describe() marks it constant_only.

    control-default gives the value or a fallback
    
        
    It gives value, or fallback when the value is None. A branch not chosen still skips it, since a skip wins. fallback can be a constant. Wire fallback from another node, and you get the first of two values that isn't None.
    
        
    The source in control.py Internal
    
        
    def default[T](value: T | None, fallback: T) -> T:
    return fallback if value is None else value

    The outputs take the type wired in
    
        
    value is a type variable T, and so are the outputs. When a graph is compiled, T becomes the type on the edge into value. Wire in the int of text-length, and both branches are int. A node wired after a branch is checked against int. Wire if_true into text-uppercase.text, a str, and compiling reports it.
    
        
    With no edge into value, say a constant, the type stays Any. The palette's runs show that. There each node is alone, so control-decide's outputs are Any.

       for f in graph.describe().nodes["control-decide"].outputs])

    Widgets
    
    
    The one widget is for long texts Public
    
    
    A widget tells a host's editor how to draw an input. Compiling and running never read one.
    
    
    The package gives one widget, Textarea(), to 12 inputs. Each is the main text a node works on, which may be long. In describe() it's written {'type': 'textarea', 'rows': 4}.

    Loops and tables
    
    
    From a table into a loop and back Public
    
    
    A table is one value. series-split takes it apart, so the nodes after it run once per row. table-collect puts the rows back into one table, with a new column for what was worked out for each. How loops work is on the Series and tables page. This is the package's own example, from its README.
    
  
    
  
    
    
    
      
    @reg.node("read-contacts", title="Read contacts", description="...")
def read_contacts(csv: str) -> Table:
    return pl.read_csv(io.StringIO(csv))

@reg.node("greet", title="Greet", description="...")
def greet(name: str) -> str:
    return f"Hello {name}"

contacts = Graph.compile(make_graph(
    read_contacts, series.split, greet, tables.collect,
    edges=[("read-contacts.result", "series-split.value"),
           ("series-split.result.name", "greet.name"),
           ("series-split.result", "table-collect.rows"),
           ("greet.result", "table-collect.greeting")],
    constants={"table-collect.columns": ["greeting"]},
    outputs={"contacts": "table-collect.result"}), reg)

d = contacts.describe()
print({n: d.nodes[n].per_item_of for n in ("series-split", "greet", "table-collect")})
print([(i.field.name, i.field.type) for i in d.nodes["table-collect"].inputs])
print(contacts.run({"csv": "name\nIda\nBo\n"}).outputs["contacts"].to_dicts())

    greet takes one name, so it runs once per contact (per_item_of). table-collect runs once, with every row.
    
      
    Each name in columns becomes an input of table-collect, here greeting. Its hook compute_added_inputs adds it when the graph is compiled. compute_outputs then works out the table's type. Here the rows are a bare Table, of columns not known in advance, so the result is a bare Table too. With rows typed by a TypedDict, the result's columns are typed.
    
      
    Its output is worked out when the graph is compiled, so make_graph is told the graph returns it, with outputs=.
    
      
    series-collect is the plain way back. It gives a list of each item's value. series-stack stacks one table per item into one table.
    
      
    Wire the whole table into greet.name instead, and compiling reports a problem.

    Good to know
    
    
    Six details and their runs
    
  
    
  
    
    
    
      
    A slow pattern fails its node
    
      
    The regex nodes use the regex package, and every search has a timeout of 2 seconds (regex_ops.TIMEOUT). On (a+)+$ against a run of a's and a b, Python's re can run practically forever. The regex package finishes a run of 30. On 5,000 it still runs past the timeout, and the node fails. Here is regex-match on both: the run's status, then its outputs or the code it failed with.
    
      
    30    complete {'result': False}
5000  failed   pattern_timeout
    
    
    
    
    
      
    Rounding the way people do
    
      
    math-round rounds a half away from zero, on the number as it's written. The float closest to 0.125 is a little less than 0.125, so Python's own round gives 0.12.
    
      
    print(m.round_to(2.5), m.round_to(-2.5), m.round_to(0.125, 2), round(0.125, 2))

    What counts as empty
    
      
    logic-is-empty is true for None and for anything with a length of 0, a table of no rows included. 0 and a text of one space are not empty.
    
      
    print(logic.is_empty(pl.DataFrame({"name": []}, schema={"name": pl.String})),
      logic.is_empty(0), logic.is_empty(" "))

    JSON has no NaN
    
      
    Python's json reads NaN and Infinity, reads 1e999 as inf, and writes inf back. JSON has none of them, so json-parse and json-stringify refuse them with not_json.
    
      
    for text_in in ("NaN", "1e999", '{"a": 1}'):

    except NodeError as error:

    Why it's built this way
    
    
    The package's design choices
    
  
    
  
    
    
    
      
    Each module has a registry and is one category.
    
      
    A host takes the kinds of node it wants with add_subregistry, or filters the whole package by category, and both give the same nodes. No node in the package sets a category of its own, so each takes its module's.
    
      
    Cost: a host that adds the whole package and then one module again gets duplicate_node_id. It picks one or the other.
    
    
    
    
    
      
    The package uses only conductor's public names.
    
      
    It needs nothing from conductor._internal, so a change inside the engine that keeps the public modules the same doesn't touch it.
    
    
    
    
    
      
    A node for any type is generic and needs a hook only for names.
    
      
    control-decide, control-switch, control-default, logic-equals, series-split, series-collect and series-stack declare a type variable. A node after them is checked against the real type, not Any. Six of them need no hook. control-switch is the exception. Its branch names come from a hook, since cases names them, and their type comes from T.
    
      
    Cost: with no edge into the value, such as a constant, the type stays Any.
    
    
    
    
    
      
    A hook is used only where a constant names the fields.
    
      
    The branches of control-switch and the new columns of table-collect are named in the graph, so a hook works them out when it's compiled. Each input whose value a hook reads takes only a constant. An input whose type it reads, such as value: type, is wired as usual.
    
      
    Cost: cases and columns can't come from an edge. They're written when the graph is drawn.
    
    
    
    
    
      
    A branch not chosen is SKIPPED, and branches join at an input.
    
      
    A branch is an output whose default is SKIPPED, and a call gives a value to at most one branch of a node. A node with several branches wired into one input takes the one that has the value. So the package has no join node.
    
    
    
    
    
      
    The decision doesn't parse a condition.
    
      
    control-decide takes a yes or no. Small nodes work it out: logic-equals, logic-is-empty, logic-not, text-contains, regex-match. So there's no expression language to learn or to check.
    
      
    Cost: a condition is one more node in the graph.
    
    
    
    
    
      
    A switch always has other.
    
      
    A case none of the branches names still goes somewhere. That's why a case may not be called other (case_named_other).
    
    
    
    
    
      
    A widget is given only where it adds something.
    
      
    Without a widget, the editor picks a control from the input's type. The 12 inputs that take a long text get a Textarea. The short ones keep the editor's default.
    
    
    
    
    
      
    A failure has a code of its own.
    
      
    A node that can't do its job raises a NodeError with a code such as division_by_zero or invalid_replacement. A host can tell them apart by code. A NodeError other than an ExternalError, which no node here raises, isn't retried, even with retry_on=(Exception,), since the same arguments would fail the same way.
    
    
    
    
    
      
    The nodes only compute, so every one is tested by running it.
    
      
    None of them needs an outside service, so test_catalog.py gives every node an example, and a test checks that none is missing. check_registry then runs the whole registry in one test. A host sees none of this, but check_registry is the same one test a host can run on its own registry.
