    A node and its types

    A node is a plain Python function under @node. Conductor reads the function's typed signature once, when the decorator runs, and turns its parameters into inputs and its return type into outputs.

    ← The overview

    The signature is the interface.

    A definition is frozen and registers nothing.

    A wrong declaration fails at import.

    Publicwhat you import, write or read back

    Internalhow conductor does it inside; you never import it, and it can change in any release

    What @node reads

    The signature is read once

    Tap a part of the node to see what conductor makes from that part.

    Param

    A Param says more about an input or output

    Annotated[int, Param(...)] adds a title, a widget, limits and choices. The limits and choices check a value. The title, description and widget only reach the editor, so two fields that differ only in their title have the same type.

    Params stack, and the later one wins

    For each argument, the last Param that sets it wins, and None counts as not set.

    Line = Annotated[str, Param(widget=TextInput(), title="Line")]

@node("split", title="Split", description="Splits a text.")
def split(text: str,
          separator: Annotated[Line, Param(min_length=1, title="Separator")] | None = None,
          ) -> list[str]:
    return text.split(separator)

sep = split.describe().inputs[1]
print(sep.title, sep.widget, sep.type, sep.json_schema)
    Separator {'type': 'text-input'} str {'anyOf': [{'minLength': 1, 'type': 'string'}, {'type': 'null'}]}

    Choices go in Param(choices=)

    Write the type plainly and list each value once in Param(choices=). The field then takes only those values, and its schema lists them as its enum. A Choice gives a value a title, written by position or with keywords. A bare value is titled by its text. A Literal gives the same choices and enum, but it can't give them titles.

    @node("size", title="Size", description="Picks a size.")
def size(
    pick: Annotated[str, Param(choices=[Choice("s", "Small"),
                                        Choice(id="m", title="Medium")])],
    untitled: Annotated[str, Param(choices=["s", "m"])] = "s",
    literal: Literal["s", "m"] = "s",
) -> str: ...

for field in size.describe().inputs:
    print(field.name, field.type, [(c.id, c.title) for c in field.choices],
          field.json_schema)
    pick str [('s', 'Small'), ('m', 'Medium')] {'enum': ['s', 'm'], 'type': 'string'}
untitled str [('s', 's'), ('m', 'm')] {'enum': ['s', 'm'], 'type': 'string'}
literal str [('s', 's'), ('m', 'm')] {'enum': ['s', 'm'], 'type': 'string'}

    On a node's input or output, pydantic's Field(...) is refused (pydantic_field_in_hint). Pydantic's own metadata, like annotated_types.Ge(0), still works.

    The return type

    Four shapes of output Public

    The return type says what the outputs are, and what the function must hand back on each call. Pick a shape. The outputs listed are what describe() printed for each node.

    How a type is named

    A class's id and title come from a table or a declaration Public

    Conductor names its own types from one fixed table. A class of the host's own is named with @host_type. Nothing falls back to a class's name.

    @host_type("celsius", title="Celsius")
class Celsius(BaseModel):
    degrees: float


@host_type("temperature", title="Temperature", accepts=[Celsius])
class Temperature(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    degrees: float


registry = NodeRegistry()

@registry.node("report", title="Report", description="Says how warm it is.")
def report(temperature: Temperature, count: int, ratio: float) -> str: ...

@registry.node("measure", title="Measure", description="Measures the temperature.")
def measure(ok: bool) -> Celsius: ...

for t in registry.describe().types:
    print(f"{t.id:12} {t.title:14} accepted_as={t.accepted_as}")

    Where a value of each type may go

    Each row is a type an output has. A tick is an input type it may be wired into, from its accepted_as above. Tap a row.

    Celsius goes into Temperature only because Temperature lists it in accepts. The model still reads the value itself, here through from_attributes. The list is worked out from subclassing and accepts, so nobody keeps it by hand.

    A class with no declaration

    @dataclass
class Unnamed:
    kroner: int

def total(values: list[Unnamed]) -> int: ...

try:
    node("total", title="Total", description="Adds up amounts.")(total)
except NodeDeclarationError as error:
    print(error.problems[0].type)
    print(error)
    type_not_named
total (version 1).values: __main__.Unnamed is the type of a field, and it has no @host_type. Write @host_type("unnamed", title="Unnamed") above the class.

    What @host_type checks

    It checks its arguments when the class statement ends. The id is one word and not one of conductor's own, the title isn't empty, and accepts holds only classes. Pydantic must be able to check the class. A subclass of a builtin, like class Email(str), is checked as the builtin and then made the subclass.

    registry.types holds the classes its nodes' fields name, by id, and any it is given as types=. Two classes under one id on one registry raise duplicate_type_id.

    Fields a graph decides

    Two hooks are called when a graph is compiled

    Some inputs and outputs can't be written in a signature, because the graph's author decides them. A node that adds up as many numbers as a constant says is one. A hook is a plain function that works them out. compute_added_inputs returns inputs to add, which the function takes as **values. compute_outputs returns every output, and the function then returns a mapping by name.

    def operands(count: int) -> dict[str, type]:
    return {f"value_{i}": float for i in range(count)}


def branches(names: str, value: type) -> dict[str, Any]:
    return {name: (value, SKIPPED) for name in names.split(",")}


@registry.node("sum", title="Sum", description="Adds up numbers.",
               compute_added_inputs=operands)
def sum_of(count: int, **values: float) -> float:
    return sum(values.values())


@registry.node("pick", title="Pick", description="Sends a value down the branch it names.",
               compute_outputs=branches)
def pick(value: Any, names: str, chosen: str) -> dict[str, Any]: ...


print(sum_of.compute_added_inputs.values_of)
print(pick.compute_outputs.values_of)
print([(f.name, f.constant_only) for f in sum_of.describe().inputs])

graph = Graph.compile(make_graph(sum_of, constants={"sum.count": 3},
    defaults={"sum.value_0": 0.0, "sum.value_1": 0.0, "sum.value_2": 0.0}), registry)
print([i.field.name for i in graph.describe().nodes["sum"].inputs])
print(graph.run({"value_0": 1.0, "value_1": 2.0, "value_2": 3.5}).outputs)

    What a hook's parameter gets

    a plain parameter
    The constant of the input with the same name, or else its declared default.
    a parameter annotated type
    The type an edge brings to that input, or Any until one does. Only compute_outputs may ask for it, since added inputs are worked out before any edge is read.
    **added: type
    On compute_outputs of a node that also adds inputs: the type arriving on each added input.

    A hook returns {name: type hint}, or {name: (type hint, default)}. A default of SKIPPED makes an output a branch, as branches does. Each field is held to the rules @node holds a declared field to. A hook that raises doesn't stop compiling. It becomes the problem compute_hook_raised on its node, with only the exception's class in ctx.error, and its traceback goes to the conductor logger. A hook that raises a NodeError is compute_hook_failed instead, with the error's message in ctx.reason and its code in ctx.error. A hook that returns a field @node would refuse, or a name a field can't have, is compute_hook_returned_invalid, whose ctx.errors says what is wrong.

    [('compute_hook_raised', ('bad',), 'ValueError')]

    Where an output's type should follow what arrives on an edge, a type variable says it without a hook: def keep[T](value: T) -> T.

    Beside the inputs

    The run's context and the node's Policy

    The context is one object from the host

    A host often has things many nodes need, like the person running the graph or an HTTP client. It passes them as one object, context=, when it starts or resumes a run. A node takes it as its first parameter, typed Context[X]. That parameter isn't an input.

    A node may name the registry's class, a base of it, or a Protocol, which is how a pre-built node asks for only the members it uses. Compiling checks a Protocol's members by name only. Their types are the host's type checker's job. Below, lookup asks for a Protocol the registry's class doesn't meet.

    registry = NodeRegistry(context_type=HostContext)

@registry.node("sign", title="Sign", description="Signs a text.")
def sign(ctx: Context[HostContext], text: str) -> str:
    return f"{text}, {ctx.caller}"

@registry.node("lookup", title="Lookup", description="Looks a key up.")
def lookup(ctx: Context[HasDatabase], key: str) -> str: ...

print(sign(HostContext("Ida"), "Done"))
print(list(sign.inputs), sign.context)
g = Graph.compile(make_graph(lookup), registry)
for p in g.problems:
    print(p.type, p.loc, p.msg)

    A Policy says how the engine calls the node

    The engine reads a node's Policy when it calls the node, as Running and streaming shows. A subgraph has none, since its inner nodes run by their own.

    fielddefaultwhat it says
    concurrencyNoneMost calls at once in the whole process, at least 1.
    retries0How many more times a failed call is tried.
    retry_delay1.0Seconds before the first retry. Each later one waits twice as long.
    attempt_timeoutNoneSeconds one attempt may take.
    retry_on()Exception classes to retry besides ExternalError.
    reuse_when_inputs_matchTrueWhether a run made from another (run.again, run.with_inputs, run.with_forgotten) may reuse a result.
    costs_nothingFalseWhether resume(only_costs_nothing=True) may call it.

    Policy is a frozen pydantic dataclass read strictly, so a wrong value raises where it is written. So does a keyword it doesn't have. A node whose concurrency is 2 or more, or that has an attempt_timeout, is called on threads. Any other is called on the scheduler's own thread, retries included. Policy.threaded says which.

    p = Policy(concurrency=4, retries=2)
print(p.threaded, Policy().threaded, Policy(attempt_timeout=5).threaded)
for bad in ({"retries": "2"}, {"concurrency": 0}, {"retries": True}, {"retry": 2}):
    try:
        Policy(**bad)
    except ValidationError as error:
        print(bad, "->", error.errors()[0]["type"])

    Versions and Upgrade

    A new version replaces the one before it Public

    A graph record names the version of each node it uses. A new version is a @node with the same id that names the one before it in replaces=. The registry holds the newest. The older ones are plain definitions, reached through versions. registry.upgrade moves one node of a record forward, a step at a time. Step through it.

    @node("greet", title="Greet", description="Greets a person by name.")
def greet_v1(name: str) -> str:
    return f"Hello {name}"

@node("greet", title="Greet", description="Greets a person.",
      replaces=greet_v1, upgrade=Upgrade(renamed_inputs={"name": "person"}))
def greet_v2(person: str) -> str:
    return f"Hello {person}"

def _split(values: dict) -> dict:
    first, _, last = values.pop("person").partition(" ")
    return {**values, "first": first, "last": last}

@registry.node("greet", title="Greet", description="Greets a person by first and last name.",
               replaces=greet_v2, upgrade=Upgrade(rewrite=_split))
def greet(first: str, last: str) -> str:
    return f"Hello {first} {last}"

print(list(greet.versions), greet.versions[1] is greet_v1, "greet" in registry, len(registry))
saved = make_graph(greet_v1, constants={"greet.name": "Ida Berg"})
print(Graph.compile(saved, registry).run().outputs)
    [3, 2, 1] True True 1
{'result': 'Hello Ida Berg'}

    An Upgrade is needed only when a version drops an input or output of the one it replaces. A dropped input needs a rename or a rewrite. A dropped output needs a rename, since what has to move is the edges out of it. Without one, the declaration raises upgrade_missing. version= is one past the version replaced, or 1, unless the node gives its own number, which must be above the one it replaces.

    Declaration faults

    A mistake in a node fails where it is written Public

    @node, subgraph, @host_type, Param and NodeRegistry raise NodeDeclarationError, which is a TypeError. DECLARATION_PROBLEMS has 62 kinds, each with a code of its own. Here are 14 of them, each as it was raised by running it.

    A fault in a graph is a Problem in graph.problems instead, as Problems shows.

    The registry

    A registry holds the nodes a host offers Public

    @registry.node takes the same arguments as @node and also adds the node. add takes definitions made elsewhere, and add_subregistry copies another registry's nodes in.

           tags=["case"], extra={"icon": "A"})
def upper(value: str) -> str: ...

@node("lower", title="Lowercase", description="Small letters.", category="Case")
def lower(value: str) -> str: ...

host = NodeRegistry(tags=["core"])
host.add_subregistry(text)
host.add(lower)
for d in host:
    print(d.id, repr(d.category), d.tags, dict(d.extra))

    Defaults
    A node that comes in gets the registry's defaults. The registry's tags come first, then the node's own. A node's own category wins, and extra merges key by key, the node's keys winning. A subregistry's defaults are applied first, then the outer registry's.
    Copies
    The definition lower keeps its own empty tags. The registry holds a copy with its defaults. The name upper, made by @text.node, is bound to the copy text holds.
    One way to swap
    add raises on an id that is already there. replace and remove are explicit. A registry isn't a Mapping, so there is no get that answers a misspelt id with None.
    context_type
    NodeRegistry(context_type=X) names the class of the run's context, and is a NodeRegistry[X] to a type checker. A subregistry must name the same class or none.
    describe()
    A RegistryDescription. It has a NodeDescription per node and a TypeDescription per type.

    Why it's built this way

    The design choices of this part Public

    The signature is the node's interface.

    The engine, the checks and the editor all read the one signature. So an input is declared in one place, and a node stays callable like its function, which makes calling it its unit test.

    @node returns a frozen definition and registers nothing.

    A definition belongs to no registry, so it can go into any of them, and what a host offers is written in one place, the registry.

    Cost: nobody can find a node until it is added to a registry.

    A declaration fault raises at import, and a graph fault becomes a Problem

    Only the node's developer meets a fault in a declaration, so it fails when the module loads, with a message written for them. A fault in a graph is met by whoever drew it, so it is reported on its node and compiling goes on.

    Param is where a field's title, limits and choices go.

    Pydantic's Field(...) is refused in a node's hint, so a limit isn't written with both Field and Param. Param is pydantic metadata, so the same limits work in a host's own model.

    Cost: a pydantic user writes Param where they would reach for Field. The error names the Param to write.

    A class's id and title are declared, not read from its name.

    The id is what an editor and a saved graph call the type, and the title is what a person reads. So both are written on purpose, and checked when the class is defined.

    Cost: every class of the host's on a field, except a TypedDict, needs @host_type, and a subclass needs its own.

    @host_type is a decorator, not a base class.

    A base class's hook runs before @dataclass has made the class, so it can't check a dataclass, and a library's class can't be given one.

    accepts is a list of classes.

    A list is data an editor can show before anything runs, in accepted_as.

    Cost: a rule that isn't a list of classes can't be said.

    Hooks run when a graph is compiled.

    A hook reads constants and the types edges bring, so every node's fields are known before a run, and graph.describe() shows them.

    Cost: a node's fields can't follow a value that arrives at run time. A type that follows an edge needs no run-time value, since a type variable or a hook parameter annotated type can say it.

    Compiling never upgrades.

    A saved graph runs the version it names. Moving it is a call the host makes, registry.upgrade, and the result is a record to show the graph's author.

    Cost: old versions stay in the code, as plain @node definitions, for as long as saved graphs use them.

    The run's context isn't an input.

    No edge reaches it and a run never saves it, so a host can pass live objects like a client. A test passes it as the first argument.

    Cost: whether a call's earlier outcome is reused doesn't look at the context. Policy(reuse_when_inputs_match=False) is for a node that reads more than its inputs.
