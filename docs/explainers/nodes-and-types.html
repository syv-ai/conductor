    A node and its types

    A node is a plain Python function under @node. Conductor reads the function's typed signature once, when the decorator runs, and turns its parameters into inputs and its return type into outputs.

    ← The overview

    The signature is the interface.

    A definition is frozen and registers nothing.

    A wrong declaration fails at import.

    Publicwhat you import, write or read back

    Internalhow conductor does it inside; you never import it, and it can change in any release

    Param

    A Param says more about an input or output

    Annotated[int, Param(...)] adds a title, a widget, limits and choices. The limits and choices check a value. The title, description and widget only reach the editor, so two fields that differ only in their title have the same type.

    Params stack, and the later one wins

    An alias can be wrapped in another Param. How the two merge is in the reference: python -m conductor.about the-node-contract.

    Line = Annotated[str, Param(widget=TextInput(), title="Line")]

    Choices go in Param(choices=)

    Write the type plainly and list each value once in Param(choices=). The field then takes only those values, and its schema lists them as its enum. A Choice gives a value a title, written by position or with keywords. A bare value is titled by its text. A Literal gives the same choices and enum, but it can't give them titles.

    An instance of the dataclass, one output per field. A dataclass with @host_type is one value instead, not a dataclass of outputs. A field whose default is SKIPPED is a branch.     How a type is named

    A class's id and title come from a table or a declaration Public

    Conductor names its own types from one fixed table. A class of the host's own is named with @host_type. Nothing falls back to a class's name.

    Fields a graph decides

    Two hooks are called when a graph is compiled

    Some inputs and outputs can't be written in a signature, because the graph's author decides them. A node that adds up as many numbers as a constant says is one. A hook is a plain function that works them out. compute_added_inputs returns inputs to add, which the function takes as **values. compute_outputs returns every output, and the function then returns a mapping by name.

    def operands(count: int) -> dict[str, type]:
    return {f"value_{i}": float for i in range(count)}


def branches(names: str, value: type) -> dict[str, Any]:
    return {name: (value, SKIPPED) for name in names.split(",")}

    Beside the inputs

    The run's context and the node's Policy

    The context is one object from the host

    A host often has things many nodes need, like the person running the graph or an HTTP client. It passes them as one object, context=, when it starts or resumes a run. A node takes it as its first parameter, typed Context[X]. That parameter isn't an input.

    A node may name the registry's class, a base of it, or a Protocol, which is how a pre-built node asks for only the members it uses. Compiling checks a Protocol's members by name only. Their types are the host's type checker's job. Below, lookup asks for a Protocol the registry's class doesn't meet.

    A Policy says how the engine calls the node

    The engine reads a node's Policy when it calls the node, as Running and streaming shows. A subgraph has none, since its inner nodes run by their own.

    Each field and its default:

    print(Policy())
    Policy(concurrency=None, retries=0, retry_delay=1.0, attempt_timeout=None, retry_on=(), reuse_when_inputs_match=True, costs_nothing=False)

    What each field means is in the reference: python -m conductor.about versions-and-policies, with retries in retries-and-timeouts, reuse in running-again and costs_nothing in running. Running and streaming and Saved runs and reuse show them at work.

    Policy is a frozen pydantic dataclass read strictly, so a wrong value raises where it is written. So does a keyword it doesn't have. A node whose concurrency is 2 or more, or that has an attempt_timeout, is called on threads. Any other is called on the scheduler's own thread, retries included. Policy.threaded says which.

    Versions and Upgrade

    A new version replaces the one before it Public

    A graph record names the version of each node it uses. A new version is a @node with the same id that names the one before it in replaces=. The registry holds the newest. The older ones are plain definitions, reached through versions. registry.upgrade moves one node of a record forward, a step at a time. Step through it.

    registry = NodeRegistry()


@node("greet", title="Greet", description="Greets a person by name.")
def greet_v1(name: str) -> str:
    return f"Hello {name}"

@node("greet", title="Greet", description="Greets a person.",
      replaces=greet_v1, upgrade=Upgrade(renamed_inputs={"name": "person"}))
def greet_v2(person: str) -> str:
    return f"Hello {person}"

def _split(values: dict) -> dict:
    first, _, last = values.pop("person").partition(" ")
    return {**values, "first": first, "last": last}

@registry.node("greet", title="Greet", description="Greets a person by first and last name.",
               replaces=greet_v2, upgrade=Upgrade(rewrite=_split))
def greet(first: str, last: str) -> str:
    return f"Hello {first} {last}"

print(list(greet.versions), greet.versions[1] is greet_v1, "greet" in registry, len(registry))
saved = make_graph(greet_v1, constants={"greet.name": "Ida Berg"})
print(Graph.compile(saved, registry).run().outputs)
    [3, 2, 1] True True 1
{'result': 'Hello Ida Berg'}

    The record as it was saved

    The record names version 1 and gives name a constant. Compiled as it is, it runs version 1, which is still in the chain.

    print(saved.model_dump(mode="json")["nodes"]["greet"])
    {'node': 'greet', 'inputs': {'name': {'constant': 'Ida Berg'}}}

    Version 2's Upgrade renames an input

    renamed_inputs carries what the input got, here its constant, over to the new name.

    step = registry.upgrade(saved, "greet", to=2)
print(step.model_dump(mode="json")["nodes"]["greet"])
    {'node': 'greet', 'version': 2, 'inputs': {'person': {'constant': 'Ida Berg'}}}

    Version 3's Upgrade rewrites the values

    The rewrite gets the node's constants as one dict and returns them for the newer version. It pops person, since every key it returns is written.

    moved = registry.upgrade(saved, "greet")
print(moved.model_dump(mode="json")["nodes"]["greet"])
print(Graph.compile(moved, registry).run().outputs)
    {'node': 'greet', 'version': 3, 'inputs': {'first': {'constant': 'Ida'}, 'last': {'constant': 'Berg'}}}
{'result': 'Hello Ida Berg'}

    An Upgrade is needed only when a version drops an input or output of the one it replaces. A dropped input needs a rename or a rewrite. A dropped output needs a rename, since what has to move is the edges out of it. Without one, the declaration raises upgrade_missing. version= is one past the version replaced, or 1, unless the node gives its own number, which must be above the one it replaces.

    Why it's built this way

    The design choices of this part Public

    Why a definition is frozen and registers nothing, why Param is the one spelling of a limit, why a class's id is declared, why @host_type is a decorator with a list of accepts, and why compiling never upgrades, is in the design guide: "The front door and the registry", "The graph record and make_graph" and "Where conductor meets pydantic". Three more choices are this page's own.

    A declaration fault raises at import, and a graph fault becomes a Problem

    Only the node's developer meets a fault in a declaration, so it fails when the module loads, with a message written for them. A fault in a graph is met by whoever drew it, so it is reported on its node and compiling goes on.

    Hooks run when a graph is compiled.

    A hook reads constants and the types edges bring, so every node's fields are known before a run, and graph.describe() shows them.

    Cost: a node's fields can't follow a value that arrives at run time. A type that follows an edge needs no run-time value, since a type variable or a hook parameter annotated type can say it.

    The run's context isn't an input.

    No edge reaches it and a run never saves it, so a host can pass live objects like a client. A test passes it as the first argument.

    Cost: whether a call's earlier outcome is reused doesn't look at the context. Policy(reuse_when_inputs_match=False) is for a node that reads more than its inputs.
