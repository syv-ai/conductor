# Conductor

A general-purpose Python library that runs graphs of typed nodes. It serves any host; nothing in it is fitted to one application. The user docs are `README.md` (the first page; `docs/index.md` includes it whole), `docs/writing-nodes.md` (for node authors), `docs/OVERVIEW.md`, `docs/subgraphs.md`, `docs/serving-runs.md`, `docs/explainers/` (illustrated HTML pages, one per part of the engine, listed by `docs/explainers.md`; their samples run in `tests/test_core/test_explainer_samples_run.py`, and `docs/hooks/explainers.py` writes in the data two of them show), and the packaged reference `packages/conductor/src/conductor/about/llms.txt` (`python -m conductor.about`), the one complete reference. A rule is written out once, in the reference; the pages teach by example. The reference has no list of public names: a line `<!-- names: conductor.events -->` marks where a module's names go, and `conductor.about` writes them there from the module's `__all__`, each with the first paragraph of its docstring, so a public name is described in its docstring and ordered in `__all__`.

## Layout

- `packages/conductor/` (`syv-conductor`, import `conductor`): the engine. Five public modules, `__init__.py`, `widgets.py` (the controls), `events.py`, `testing/` (`check_registry`, one test for a whole registry, with the kinds of problem it returns in `problems.py`) and `about/` (the reference: `llms.txt`, the rules, and `problems.md`, the problems page, whose every kind of problem is written in from the function that declares it, with its example), plus `_internal/`, which has everything else. A concept there is a package whose `__init__.py` is its surface. The packages stand in layers, each importing only those below it (`utils/` at the bottom, then `base/`, `registry/` and `run/` near the top, and `make_graph/` above them all, a convenience on top of the core that nothing in it imports), and a module outside a package imports it only through its `__init__.py`. An import-linter contract in `pyproject.toml` says the layers once (`tests/test_core/test_layers.py` runs it); a module imports its own package's modules by a relative name (`from .outcome import Done`), which ruff's `TID252` keeps to its own package, and a pre-commit hook refuses an absolute import of another package's file. Inside, the same file name means the same job in every package, and a file exists only when the concept has that job: `type.py` is the class the package is named after, `read.py` how untyped data is read (a concept's schema for it, and in `types/` the functions that read a value by its type), `write.py` its JSON form, `stored.py` how a run stores one, `describe.py` what a host is shown, `validator.py` its validators, each a `Validator` (in `base/`, the `Validator` base class itself): where a value of the concept enters from outside, checked there with pydantic and trusted inside (an edge's value is checked again only where its input's type demands more than its source's, by `EdgeValidator`; the few checks that run in plain Python beside pydantic are listed once, in the reference's "Pydantic checks every value that comes in", beside the judgments that check no value, such as a run's `context=`, which is never data, by `isinstance`); a value's type check is built in its type's package, `types/`, or `table/` and `series/` for the two types conductor declares itself, since a table's and a Series' checks are their type's own (a saved run is read in `run/json/`, and a `NodeError`'s `ctx` by `NodeError`); what a host saves or sends is a pydantic model wherever its concept declares it (`ConductorModel`), and a declaration's own arguments are held to their annotations by pydantic where they are written (`Param`, `@host_type`'s `TypeDeclaration`, `Source`, `Name`), and an `Upgrade`'s where `@node` or `subgraph` reads it (`DeclarationValidator`); a validator that refuses a value raises `InvalidCallError` with the problems it found, or `NodeDeclarationError` where the value is a node's own declaration (`port/`'s). Any other file is named for the noun it is about. A concept with one job is one file, not a package, and a class whose methods share its state stays one file. - `packages/conductor-nodes/` (`syv-conductor-nodes`, import `conductor_nodes`): nodes that only compute, a registry per module.
- `packages/conductor-providers/` (`syv-conductor-providers`, import `conductor_providers`): `fastapi`, the routes that serve runs (`run_router`) over a `Worker`, which keeps runs in the `RunStore` a host writes and gives each run's metadata back to the host's `nodes_for`, `context` and run filter, with `fastapi.testing.check_run_store`, one test for a host's store. Its files: `router.py` the routes, `bodies.py` the request bodies, `problems.py` the worker's three codes and their HTTP status, `store.py` the row (`StoredRun`), the row as the worker reads it (`RunRow`, the host's row with its JSON read), the store, and `GuardedStore`, the worker's one door to the store, which reads each row once and writes it back, `state.py` the JSON the worker keeps in a row, with the replies queued while a run runs, one entry per reply, each to one waiting id, `worker.py` the worker, `held_run.py` one worker's lease on one run, `testing.py` the store check.
- `scripts/format_markdown.py`: the Markdown fixer a commit hook runs, which writes each paragraph and list item on one line and never changes a word.
- `tests/`: `test_core`, `test_nodes` (the node package), `test_providers` (`docs/serving-runs.md` on two uvicorn workers, and event JSON).
- `examples/`: Jupyter notebooks. `skills/`: agent skills for adding a node and building a graph.

Pushing a `v*` tag publishes the three packages to PyPI, at one version. The two companions import only conductor's public modules.

## Commands

```bash
uv sync                      # install everything
uv run pre-commit install    # the commit hooks: notebook outputs, ruff's fixes and format, imports, docstrings
uv run pytest tests/ -q      # the whole suite
uvx ruff@0.17.0 check --fix .  # lint, fixing what ruff can; CI runs `ruff check .` at the version the commit hook pins
uvx ruff@0.17.0 format .       # format, as the commit hook does; CI runs `ruff format --check .`
uv run mypy packages         # type-check, as CI runs it
uv run --group docs mkdocs build --strict  # the docs; CI also runs this, and executes every notebook in examples/
```

CI runs ruff's check and format check, mypy and pytest on every PR. A test whose point is a wall-clock bound is marked `slow`, and CI deselects those (`-m "not slow"`), since a busy runner misses the bound.

## Rules

- **Conductor stands alone.** No host's words ("flow", "app", an access model), no host's imports, and no concrete type declared by the core. The library's word is graph.
- **One node contract.** A node is a function under `@node`, its typed signature its interface, and `@node` returns a frozen `NodeDefinition` that registers nothing. Any type pydantic can carry travels on edges as it is; a host's own type needs no base class.
- **Behaviour is a value, not a flag.** A branch not chosen returns `SKIPPED`; a node that needs a person raises `Ask`, and its `@node` says that it may (`asks=True`). There is no role or flag on a class that tells the engine what to do.
- **Inputs and outputs a graph decides live in the hooks.** `compute_added_inputs` and `compute_outputs` are plain functions, given per version, whose parameters name the inputs they read and that return `{name: type hint}`; a parameter annotated `type` gets the type on an edge. They are the only home for inputs and outputs that depend on a graph's constants, and they are called when a graph is compiled.
- **Compiling reports, it does not raise.** Every fault in a graph is a `Problem` with a stable `type`, anchored on a node, in `graph.problems`; a failing hook is one too. A value that isn't a graph record is refused at its door with `invalid_record`, and running a graph that is not runnable raises (`InvalidCallError`).
- **Retries belong to the node's `Policy`.** Only an `ExternalError`, or an exception class named in `retry_on`, is retried; a node's own `NodeError`, an output its type refuses and an `Ask` never are. Every run-time failure carries a `Problem`; a node's own exception other than a `NodeError` goes to the `conductor` logger, and only its class name reaches an event.
- **One scheduler, with or without a listener.** `run.resume()` and `run.stream()` call the nodes the same way; streaming only adds the events. A node with `concurrency` 1 or `None` (the default) and no `attempt_timeout` is called on the scheduler's own thread, retries included; any other on threads.
- **What a host saves or sends is a pydantic model** on `ConductorModel` (the graph record, a problem, an event, a waiting call, how a run ended early), which refuses a key it doesn't declare, and cross JSON with pydantic's own `model_dump_json` and `model_validate_json`. Two exceptions: `Choice` takes any key (`extra="allow"`), since a choice carries every keyword it is given; and the classes of a saved run in `run/json/type.py` are plain pydantic models, since a graph's codec subclasses them with the graph's own value types, and `ConductorModel` would refuse the codec of a graph whose node returns a type with no JSON form, which a run holds until it is saved: a node may return one, and an edge carries it, but a caller's input and a person's answer are read from their JSON form and can't be one. A `Run` writes itself with `to_json()`. What compiling and running build per call stays a dataclass.
- **The widget set is open.** Conductor ships the common controls; a host subclasses `Widget` for its own. Compiling and running never act on a widget; it is only written into what a host is shown. What a value must satisfy goes on `Param` (`ge`, `le`, `max_length`, ...), where it is enforced.
- **Two definitions under one id raise** when the second is added to a registry; so does one type id from two classes.
- **Fail loud.** No defensive `None` checks or silent defaults where the state means a bug.
- **Imports.** Code outside the core library imports only from the five public modules: `conductor`, `conductor.widgets`, `conductor.events`, `conductor.testing` and `conductor.about`. Inside the core, import a name from the package that defines it, never from a file inside another package; a package's `__init__.py` is its surface and declares `__all__`, as the five public modules do.
- **Identifiers are English.**
- **Notebook outputs are stripped on commit.** Run the cells to see values.
- **Keep the docs true.** A change to public API updates `README.md`, `docs/`, `llms.txt` and the skills in the same change, and adds a `CHANGELOG.md` line under `[Unreleased]`. Keep every Python block in the docs runnable. Docs describe what the code does; where a commit message and the code disagree, trust the code.

## Coding conventions

How conductor's code is written (names, docstrings, types, validation, modules, design, tests, commits) is in `conventions/`, one file per area, and nowhere else. Read the file for each area you change. In a Claude Code session, rulecast's hooks (`.rulecast-config.yaml`) hand you the section for the file you open and flag a break when you edit or stop.

## Public API

The public API is what the five public modules list in `__all__`. Everything in `conductor._internal`, including anything with a leading underscore, is internal. A breaking change to the public API needs a major version.
